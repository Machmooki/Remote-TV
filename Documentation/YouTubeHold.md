# YouTube contextual actions: hold OK

The earlier touchpad hold sent `KEYCODE_MENU` (82) as a short press. That is a different input from holding the remote's OK button and cannot be relied upon to open a video's contextual actions.

The touchpad now requests `longSelect`. The production remote transport sends `KEYCODE_DPAD_CENTER` (23) with `START_LONG` (1), waits 800 ms, then sends the same key with `END_LONG` (2). These key/direction fields are from the pinned [Remote v2 schema](https://github.com/tronikos/androidtvremote2/blob/e664a8e1f14ee458b14c646bfb3ea46f10367051/src/androidtvremote2/remotemessage.proto) and [send_key_command reference](https://github.com/tronikos/androidtvremote2/blob/e664a8e1f14ee458b14c646bfb3ea46f10367051/src/androidtvremote2/remote.py). The duration is the app's bounded hold policy, not a protocol-prescribed value. The separate Menu button still sends keycode 82.

Gesture recognition still takes 550 ms and cancels if the finger moves 10 points. Once recognized, the short bounded OK press finishes its release even if the gesture worker is cancelled. Subsequent keys, app shortcuts and text wait for release. Disconnect cancels the press and closes that session; neither key-up nor a failure callback can affect its replacement. Failed start/end writes disable the failed session and never count as successful transmission. There is no extra SHORT OK on touch release. Appearance/layout are unchanged.

To try on the physical PLAYBOX: connect, open YouTube's video browsing screen, focus a video thumbnail, then hold the touchpad still for about **1.5 seconds** and release. Check whether that YouTube app/version opens its additional actions. Holding on the playback screen can have a different meaning. If the app ignores long OK, use its visible More/three-dot control when available. The app cannot guarantee a particular popup from a completed network write.

Protocol tests verify literal START_LONG/END_LONG bytes, duration, no Menu/SHORT OK substitution, release after gesture-worker cancellation, ordering of a following key, failures at either write, cancellation before recognition and disconnect/replacement isolation. Existing navigation, IME, recovery and UI tests remain applicable. Physical YouTube popup behavior has not been verified here; final build/results are in `Verification.md` and `TestResults.json`.
